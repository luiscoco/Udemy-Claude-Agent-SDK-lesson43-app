01

Define focused specialists

Use the agents option with separate description and prompt fields. A reviewer and a test runner have different expertise and tool capabilities.

02

Delegate through Agent

The parent invokes specialists through the real Agent tool. Inspect native tool-use IDs, child tool events and returned reports to distinguish delegation from a parent-only answer.

03

Give a clear task brief

A fresh child does not automatically receive the parent’s history or system prompt. Compare a withheld classroom label with one explicitly supplied in the delegation prompt.

04

Restrict each child’s tools

The code reviewer has Read, Grep and Glob; the test runner can execute one fixed Node test command. The intentionally flawed fixture is read-only throughout the lab.

05

Inspect concurrency and models

Request two specialists in one turn and inspect actual start/stop times. Compare inherited and Haiku reviewer models using observed IDs and SDK-reported estimates, without promising a universal speed or cost result.

06

Compare three creation paths

Run programmatic definitions, a real .claude/agents/file-reviewer.md definition loaded from project settings, and the SDK’s built-in general-purpose agent.
